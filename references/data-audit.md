# 生意经复盘数据字典与校验

## 最小数据集

每条指标记录至少包含：`metric`、`value`、`raw_value`、`period_start`、`period_end`、`scope`、`source_module`、`source_label`、`captured_at`。

## 建议字段

经营：支付金额、成交金额、有效结算GMV、支付订单、核销金额、退款金额、核销率、退款率、新客、复购。

直播：直播场次、直播时长秒数、开播账号数、观看人数、成交金额、成交券数、千次观看成交金额。保存账号级明细时包含账号名称与抖音号。

短视频：视频总量、达人视频量、自营/职人视频量、发布账号数、总播放量、平均播放量、互动量、成交金额、成交券数。达人视频是否属于总量的子集必须单独记录为 `influencer_in_total=true|false|null`。

商品/门店：成交额、券数、核销、退款、客单价、贡献占比，以及排名靠前和异常项。

## JSON 结构

  "review_month": "2026-08",
  "captured_at": "2026-08-31T18:00:00+08:00",

    "value": 576000,
    "raw_value": "160小时",
    "period_start": "2026-08-01",
    "period_end": "2026-08-31",
    "scope": "全部账号",
    "source_module": "直播分析",
    "source_label": "直播时长"
  }],
  "live_accounts": [],

## 交叉校验

1. `review_month` 必须与核心指标日期同月，且覆盖该月第一天至最后一天；若为未结束月份，顶层增加 `partial_period=true`。
2. 若存在账号级直播时长，求和后与直播总时长比较；差异不超过60秒或0.5%可视为展示取整。
3. 若存在账号级直播场次、成交金额、券数、观看人数，分别与总览核对。人数可能因跨账号去重而不可直接相加，需用 `aggregation_note` 说明。
4. `influencer_video_count` 不得大于 `video_count_total`，除非明确标记 `influencer_in_total=false` 且平台定义为两套独立口径。
5. 若同时存在达人、自营、职人分组量，只有平台明确互斥时才要求其和等于总量。
6. 总播放量与分组播放量仅在范围互斥、周期一致时求和核对。
7. 环比字段必须能找到上月同名、同范围、同来源口径指标。

## 报告中的口径标注

自然月完整数据写“统计周期：YYYY-MM-01—YYYY-MM-DD（自然月）”。未完结月写“截至YYYY-MM-DD”，所有可能继续变化的指标标注“动态数据”。无法确认包含关系时写“平台口径未明确，暂不合并计算”，不要使用含糊的“约”。

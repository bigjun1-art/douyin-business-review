# 经营复盘正文框架

## 标题及统计边界

完整自然月可用“企业全称｜YYYY年M月抖音生活服务经营复盘”；非完整月标题明确起止日或“截至M月D日”。自动发布要求标题包含配置中的企业全称，正文保留 YYYY-MM-DD 格式的起止日期，便于主体与周期核验。开头同时说明数据更新时间和必要范围，不把未完结数据写成全月结果。

## 章节关系

1. **经营结论**：先说明成交与履约现状、贡献来源、主要变化及风险。没有基期不能写“增长”或“下滑”。
2. **核心经营数据**：成交、核销、退款及内容关键指标；有合格基期才列对比，避免跨期指标拼出貌似精准的转化率。
3. **直播分析**：场次、时长、观看、成交、券数及账号贡献；把投入规模和效率分开，标明人数去重限制。
4. **短视频分析**：新增与存量、达人与商家/职人/UGC、播放与直接成交。解释数量和结果是否对应同一批内容；数量增长并不直接证明有效供给增加。
5. **商品、门店与履约**：按现有证据看头部贡献、门店差异、核销和退款。缺少关键明细时列出具体限制，不编造商品结构或承接问题。
6. **问题与行动**：每个判断连接事实，每项动作连接问题、执行对象、预期结果、观察指标和复核条件。计划安排不等于已执行，不将活动、达人合作或 AI 项目默认当作本期事实。
7. **口径及待确认项**：集中说明影响结论的缺项、范围、去重与包含关系，正文涉及处也要保留必要限定。

用户提供模板时优先保留其有效框架。章节可按业务重要性合并，不追求固定条数或字数。

## 业务判断

- “发生了什么”与“为什么”分开。仅有总数无法证明达人不匹配、内容质量差或门店承接差；原因作为有依据的待验证假设，给验证方法。
- 效率指标注明分子分母，直播观看人数与观看次数、成交券数与订单数不可互换。
- 达人排期按活动目标形成集中传播与承接安排，是否一轮覆盖节日取决于已确认的活动日历和预算；不把某个客户的临时要求推广成所有客户的规则。
- AI + Vibe Coding 企业漫剧/短剧仅在适合本次业务且有授权方案需求时纳入。写清受众、内容场景、试点范围、承接入口与评估方式，效果未经测试不作保证。
- 若需补充实时平台规则、节日日期或产品能力，先查官方或可靠来源，引用客观名称与链接，不把外部案例当作本商家经营证据。

## 语义验收

完整稿保留主体、条件、因果、例外、口径和必要解释；只删重复空话。表格承载对照数据，正文说明原因与行动。时间线按实际执行阶段组织，不机械拆到每天。正式稿不包含对话、提醒、纠错过程或“按要求修改”等自我说明。

提交前通读：结论能否在数据中定位、效率计算是否同口径、问题到行动是否连贯、不同章节是否矛盾、计划是否被误当成果。数字检查通过不能替代这一步。
